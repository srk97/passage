# Passage product contract

## Job to be done

Passage should answer “where did I see that?”, “what was I doing?”, and “give my local agent the relevant evidence” in seconds, without turning a private screen history into a cloud data set.

## Implemented scope

The current macOS vertical slice provides:

- a four-step interactive v2 onboarding whose fixture-only Memory Lens lets a person select a visual detail, reveal its appearance match, and inspect exact source proof before any access request; it then explains local/change-driven storage, separates required Screen Recording from optional App Context, and previews source-cited session/agent handoff;
- pause/resume and manual capture from the main window or menu bar, plus global open/search shortcuts;
- focused-window ScreenCaptureKit frames by default, with fail-closed behavior when the requested window disappears;
- accurate language-corrected on-device Vision OCR with low-confidence/icon cleanup and multi-panel reading order, plus app/window metadata and browser URL/domain context when optional App Context access exposes it. Schema v10 stores a content-addressed, 16 KiB-bounded semantic snapshot of the still-authoritative focused window and adds its normalized labels/values to FTS5. Focused secure password fields fail closed before pixels; secure nodes' text is not inspected or persisted. Opening a legacy low-confidence memory shows a brief local reread state, decrypts its authenticated full image only in memory, and atomically repairs text, regions, the selected row, and aligned FTS evidence behind stale/deletion guards;
- adaptive cadence, visual deduplication, inactivity pause, unchanged-screen heartbeat, and power/thermal backoff; unchanged-screen screenshot backoff applies only while the person is idle, while recent keyboard or pointer input immediately restores the selected active cadence;
- local FTS5 search across OCR, titles, app/URL provenance, and available bounded Accessibility semantics, plus a full-history Recall Navigator with time/app/website filters, stable cursor paging, local-day grouping, reversible short-activity stacks, drill-sideways facet counts, full frame inspection, screenshots, source timestamps, dynamic app icons, Open Source, and previewable Hand Off Context. A chronological stack is a UI-only projection over contiguous, exact-source changes: it shows the loaded raw count and time range, expands to every underlying frame, and never changes ranking, storage, Timeline markers, selection identity, or paging. Successful result publication keeps the current selected ID when it remains visible, otherwise selects the first result; a genuinely empty publication clears it and presents matching contextual empty copy in both split-view panes. A first page publishes before its separately guarded asynchronous facet read; selected filters remain visible/removable while app and website menus distinguish loading, unavailable-with-Retry, and genuinely empty states. Website names come only from a trusted persisted HTTP(S) URL/domain captured through browser context, optional App Context, or the focused-window address band. An older frame with neither persisted value cannot be retroactively assigned a website from OCR because its pixels do not prove a focused browser origin. Result snippets visibly emphasize FTS-marked matches;
- built-in local image-appearance Recall using the hash-pinned Meta PE-Core-S-16-384 dual encoder. Matching words publish first; a separately guarded whole-image pass refines a flat Best matches list, labels visual-only evidence and partial index coverage, respects time/app/site scope, and keeps derived Int8 vectors inside SQLCipher. For bounded person-detail wording, a second query-time phase uses native Vision face/person proposals and at most eight ephemeral PE-Core crop comparisons over the existing global shortlist. Memory Lens also lets a person drag over any retained image detail and run **Find this again**: the authenticated source is cropped only in memory, embedded through the image tower, searched under exact time/app/site filters, and excluded from its own result set. The interactive canvas owns the source aspect ratio independently from its adaptive controls, so narrow and ultrawide remembered images remain complete rather than losing image height to the action row. The source fingerprint is revalidated after retrieval; query replacement, retention, deletion, lock, or source mutation suppresses late publication. The UI labels the evidence `Looks like selected area` and explicitly disclaims object/person identity. Neither path writes crop bytes or geometry, and neither pixels nor query text leave the Mac;
- a full-height Timeline with day navigation and a draggable memory current. A neutral requested-time needle tracks the pointer synchronously while a distinct memory puck appears only for an at-or-before result explicitly correlated to that request. One rail-attached bubble distinguishes resolving, resolved-with-app-and-gap, exact, no-earlier-memory, and failed states; it clamps at both edges, replaces duplicate remote status, and exposes the same distinction through the parent adjustable accessibility value. The default rail uses two-minute gaps to focus the continuous activity around the chosen moment so sparse history cannot collapse useful markers into a dense tail. **Browse whole day** switches to complete retained-day bounds, seeks directly into unloaded history, and keeps loaded-marker coverage explicit. A returned unloaded moment is merged into the painted result set before selection, so returning to focused mode remains centered on the chosen time rather than the newest loaded span. **Revisit around this time** carries the selected Recall result into its exact saved day, loads context around anchors older than the newest page, and keeps it selected. Entering Timeline snapshots Recall's exact query and scope, then enforces a clean day-only scope with no hidden text/app/website filters; an ordinary exit restores that snapshot and selection, while Open details deliberately commits the selected day to Recall. The rail renders only truthful loaded moment/app transitions, freezes its time bounds at pointer-down, throttles cancellable at-or-before lookups locally, resolves the release position exactly, uses thumbnails during scrub/resolve, and promotes the settled moment to a complete uncropped full image;
- a visible local interpretation for narrowly recognized conversational recall wording and high-confidence calendar suffixes, used only as a literal-word rescue with an Exact words escape hatch;
- deterministic activity sessions that keep cross-app work together until a five-minute gap, with a searchable Sessions UI, a safe exact-webpage return when available, and an application-only fallback when it is not;
- one shared Context Handoff sheet for Recall moments and Sessions. It previews the exact source-cited Markdown or canonical JSON, exact artifact bytes, apps/sites, included text, coverage, and omissions before an explicit copy. Its dedicated payload cannot represent screenshots, media paths, pixel geometry, embedding vectors, full URL paths, or window titles. Whole mixed-sensitive sessions are omitted. Copy revalidates every source and records a durable receipt before touching the clipboard; lock, deletion, retention, source change, or receipt failure fails closed;
- application and focused-domain exclusions, Accessibility-reported secure-text-field suppression when App Context access is granted, sensitive-context heuristics, cursor hiding, and fail-closed behavior when an excluded-domain rule exists but a focused browser URL is unavailable;
- encrypted index, media, thumbnails, privacy preferences, and agent access receipts, plus a first dormant `MemorySegmentIndex` correctness slice. Its explicit crash-safe rebuild creates deterministic app/domain/session segments of at most 64 exact frames, validates same-frame canonical FTS matches, applies whole-session agent privacy before pagination, and binds cursors to scope/revision; an absent, building, dirty, or stale generation fails closed. It has no scheduler, consumer cutover, or million-row benchmark yet;
- age- and media-size-based retention, text-preserving image expiry, and a confirmed delete-all history action that also clears cached session intelligence and answers;
- optional, explicit per-session intelligence through provider abstractions. The current OpenAI Responses implementation defaults to `gpt-5.6-luna` with low reasoning, sends bounded text only with `store: false`, validates strict source-cited JSON for both briefs and one-session questions, and caches valid results locally under purpose-separated AES-GCM keys;
- a default-deny, audited service 0.9.0 / protocol-v5 local agent boundary with discovery, a preferred multimodal Memory Capsule, metadata-only local visual search, a count/byte-bounded text bundle, and CLI search, recent results, sessions, session-filtered retrieval, frame detail, and statistics;
- an Access History view where both explicit handoff receipts and local-agent access receipts can be inspected and cleared;
- durable remembering/paused intent across startup, permission changes, session lock, and app relaunch; an early Start Remembering choice is queued until initialization and permission allow it rather than being lost to startup timing; transient focused-window/screenshot races retry without status flapping, while repeated or action-required failures remain visible until actual recovery. One shared presentation gives the menu bar, Recall sidebar, and Capture Settings the same state title, privacy consequence, semantic tone, and stable menu glyph;
- a first-real-memory coach that treats Passage's own foreground window as a safe wait, gives paused users an in-context Start action, and names local processing. Once the first frame persists, it derives one bounded deterministic query from already indexed local evidence, runs normal Recall, and marks the proof verified only if the exact persisted frame ID appears. A miss, interruption, or error remains retryable; Skip is explicit and non-destructive, and persistence stores only status plus the opaque frame ID.

Passage has no egress by default. It contacts OpenAI only after the user explicitly clicks Enhance/Refresh Brief or submits Ask on a particular session. Every question about a session containing locally private history requires a fresh confirmation naming the exact selected moment and byte counts. Enabling a local agent separately allows that same-user process to request bounded OCR/context, normalized native semantics, and visual-match metadata through typed capabilities; Memory Capsule and visual search do not release screenshot pixels. What the provider or an enabled agent does with disclosed results is outside Passage's control.

## First-run and capture-lifecycle contract

Onboarding leads with the outcome, not a permission wall. Step 1 is a fixture-only Memory Lens: drag over the round glasses or use the accessible preset, confirm **Find this again**, open one appearance match, and reveal its exact example source. The direct manipulation is immediate, the match is deterministic, and the copy explicitly says that Passage compared appearance rather than identifying an object or person. It needs no permission, opens neither the encrypted vault nor personal history, and provides Back and Start over paths. Step 2 shows the local change-driven pipeline and makes the distinction between change checks and stored memories visible. Step 3 shows a resumable cross-app session and bounded, source-cited handoff to optional intelligence or explicitly enabled agents. Step 4 presents Screen Recording as required for remembering and App Context as optional for richer URLs/window context and secure-field awareness; each permission has its own explicit Allow action.

The user can choose **Explore Passage paused** on every page, labeled **Skip and explore paused** on the first. This completes setup without requesting access or invoking capture and records the first-memory proof as deliberately skipped, so the normal Recall workspace opens instead of immediately presenting the permission coach the person declined. Reaching the final step does not start capture: if Screen Recording is absent, the primary action asks for it; only a later explicit **Create my first memory** choice records remembering intent and starts when possible. App Context can remain off indefinitely. Before setup completes, menu-bar capture and capture-now actions are replaced by **Finish Setup**, so a background menu cannot bypass the first-run choice.

Progress and completion are separate v2 preferences. An interrupted journey resumes at the stored valid step; completion resets the step to the beginning so Settings can replay the complete story. **Review onboarding** first saves paused intent and then reopens onboarding without deleting memories or resetting system permissions, exclusions, or the provider key.

Remembering/paused intent is durable and distinct from runtime status. Choosing Start Remembering persists intent even if the store is still initializing or Screen Recording is temporarily missing. Initialization starts only when both the saved remembering intent and current permission are present. Permission refresh runs after startup and when the app becomes active: revocation pauses immediately but preserves the intent, restoration resumes a remembered intent, and a deliberately paused intent stays paused. The privacy monitor also checks the authoritative protected-data API at application launch and activation, rather than trusting notification timing alone. A session lock tears down the capture/data runtime without overwriting intent. A lock that arrives during startup is checked before the newly opened coordinator is published, so late initialization cannot restart or repopulate the UI while the session is private. The UI calls this state **History sealed** and explains that macOS protected files are unavailable; it does not claim the visible desktop is locked. If the OS keybag remains unavailable after an apparently successful sign-in, Passage stays sealed and macOS-level recovery is still required.

## Privacy behavior

Passage evaluates the focused context before asking ScreenCaptureKit for pixels and evaluates it again when a still image arrives. By default it asks `SCScreenshotManager` for that exact window and never opens a live screen-sharing stream. If the window disappears, the context becomes private, optional App Context access reports that a secure password field has focus, or identity changes during delivery, Passage discards the candidate before hashing, OCR, or persistence. It never silently widens a focused-window request into display capture. User-excluded application bundles are also removed from the optional display filter.

When App Context access is granted, Passage may collect a shallow semantic snapshot only from that same non-sensitive focused window. The walk is capped at 192 visited nodes, depth 7, and 16 KiB, and the focused context is checked before and after it. Hidden nodes are skipped. A secure node is recognized from role/subrole before its label or value is read, is never traversed, and cannot contribute indexed or agent-visible text. App Context can remain off; then no Accessibility snapshot is stored and Passage does not claim Accessibility-based password-field awareness.

The initial application exclusions are 1Password, 1Password 7, Keychain Access, Passwords, and Bitwarden. Focused-domain rules include subdomains. If one or more domain rules exist and the focused browser does not expose its current URL, Passage skips that browser.

Focused-window capture prevents unrelated background windows from entering the normal pipeline. If the user explicitly turns that default off, domain exclusion is not display-wide content recognition: an excluded site visible elsewhere on the selected display can be included while another permitted app/site is focused. See [Security and threat model](SECURITY.md) for the complete limitation.

## Storage and deletion behavior

A random root is stored in the login Keychain as device-only, available only while unlocked, and non-synchronizing, then split with HKDF-SHA256 into purpose-specific keys. The current manually Developer ID-signed package lacks the authorized application-identifier entitlement/provisioning needed for the data-protection Keychain, so that backend remains future packaging work. SQLCipher protects the searchable database, FTS index, materialized sessions, URLs/OCR, and agent receipts. AES-256-GCM protects each screenshot and thumbnail, privacy preferences, cached session briefs, and explicit-question answers under separate derivation purposes. A distinct derived-and-hashed value supplies a stable device-local API safety identifier without disclosing vault key material. The OpenAI API key is stored separately as a non-synchronizing, device-only, when-unlocked Keychain item and is never written to preferences, history, or logs.

New full-size images prefer HEIC and fall back to JPEG; thumbnails remain JPEG. OCR boxes use a versioned binary format with UTF-8 offsets into the canonical OCR text instead of duplicating box strings. Schema v10 content-addresses bounded Accessibility snapshots by their canonical SHA-256 hash, stores them inside SQLCipher, and rebuilds the row-ID-aligned FTS table with an `accessibility_text` column. Visual model metadata, Int8 vectors, frame associations, and fixed angular-shortlist blocks also remain inside SQLCipher. Retention runs after a successful capture, no more than once per hour. It first removes complete frames older than the age limit, then expires oldest visual files until encrypted media is under the storage target or no indexed visual remains to expire; with the default setting, their OCR/FTS/provenance rows remain searchable. Session membership and representatives are repaired when retention changes their frames. Delete-all pauses capture, removes every frame/index/session row, attempts to unlink each referenced media file, and clears both encrypted intelligence caches; it intentionally leaves agent access receipts until the user clears those separately. Media removal is best-effort and is not transactionally coupled to the database, so filesystem errors can leave orphaned encrypted files and keep the vault above the target.

Deletion is not guaranteed physical erasure from APFS/SSD blocks, Time Machine, filesystem snapshots, backups, or copies made before deletion.

## Session-intelligence disclosure contract

Enhancement uses only the selected session's bounded textual evidence: local frame IDs and timestamps, application/window/domain/URL context, and OCR snippets. The newest evidence gets first claim on the 20,000-byte source-text budget, then retained moments are sent chronologically. The request type cannot carry screenshots, thumbnails, media paths, OCR geometry, or screen dimensions, and the provider request declares no tools. OCR and every other source field are instructed as untrusted quoted evidence rather than executable directions.

OpenAI is the implemented provider, but the product boundary is a provider protocol so another provider can be added without weakening the shared input/output contract. Responses must conform to a strict JSON schema. The title, summary, and where-left-off claims must cite only supplied frame IDs; invalid citations reject the result, while invalid next-action items are dropped. The result cache identity combines the session ID with a SHA-256 fingerprint of exactly what was sent, so source changes invalidate it. Sessions containing private local history are eligible only after a dedicated confirmation; the local-agent `sessions` capability omits them entirely.

Ask selects evidence locally before any provider call. It extracts at most six literal alphanumeric terms from the normalized question, performs one exact session-filtered FTS query, re-checks session membership, prioritizes up to 12 relevant hits, adds up to eight recent context moments, deduplicates frame IDs, and then fits the question plus source text into one 20,000-byte limit. URL credentials, query strings, and fragments are stripped. The immutable prepared disclosure drives private-session confirmation, so editing the field or switching sessions cannot change what the approval submits.

The question provider returns either one to four short claims with one to six supplied frame IDs each or `insufficient_evidence` with no free-form prose. Empty, oversized, duplicate, uncited, or out-of-session claims reject the whole answer. Its separate encrypted cache identity covers feature/schema version, normalized question, selected-session ID, exact bounded evidence, provider, and model. Cache corruption stops locally and never triggers an automatic paid disclosure. Session changes, key removal, history deletion, lock, and explicit Cancel suppress late publication.

## Agent access contract

The CLI cannot open the encrypted database and never receives the vault key. It sends one bounded JSON request over an owner-only local socket while the Passage app is running and the session is unlocked. Protocol v5 / service 0.9.0 exposes offline version/help, live capabilities/health, `memoryCapsule`, `visualSearch`, `bundle`, `sessions`, `search`, `recent`, `frame`, and aggregate `statistics`. The CLI's preferred `remember` command requests a Memory Capsule; a returned activity-session ID can scope remember, bundle, search, and recent. The app verifies that the peer has the current user's effective UID, checks the declared client identifier against an empty-by-default allow list, executes only the requested capability, and records a receipt.

A Memory Capsule performs saved-text and local visual retrieval together, re-resolves every candidate and its current activity-session identity through the private-safe primary store, fuses the surviving ranks, and returns a canonical byte-budgeted manifest with source IDs/timestamps, provenance, bounded OCR, at most eight normalized Accessibility nodes per source when available, visual similarity/error metadata, coverage, selection reasons, and explicit omissions. Visual Search and Memory Capsule now hydrate each bounded candidate set with one agent-safe store read rather than one lookup per candidate, while preserving first-occurrence order and fail-closed omissions. Any activity session containing a sensitive moment is excluded as a whole. Visual associations are admitted only while their source fingerprint still equals the retained frame fingerprint; stale cache metadata cannot supply session membership. It defaults to 8 results / 64 KiB and permits at most 24 results / 512 KiB. **It never returns screenshots or pixel bytes.** Media paths, OCR geometry, embedding vectors, and display/window identifiers are also excluded. Capsule URLs are reduced to site provenance by discarding credentials, paths, query strings, and fragments. Standalone `visualSearch` is likewise metadata-only and reports local index coverage; the older schema-v2 `bundle` remains the lower-cost text-only path.

Bundle manifests carry exact disclosed frame IDs, timestamps, app/title/domain/URL provenance, requested/matched/disclosed counts, a truncation flag, and their canonical encoded byte count. The handler performs one-result look-ahead so a result cap is visible, omits sensitive frames, truncates Unicode safely, and never includes screenshots, media paths, or OCR geometry. The legacy `frame` diagnostic can return encrypted media-path metadata, but not decrypted screenshot bytes. Session discovery independently forces `includeSensitive = false` and filters again, so a mixed private session is omitted; its successful response is audited by returned summary count rather than by expanding all member frame IDs. Every allowed result still requires a durable audit receipt before it crosses the socket.

A successful receipt is committed before its evidence is returned. It includes the declared client, command/capability, bounded query and filter summary, peer UID, returned frame IDs/count, time, and outcome. Caller-controlled summary fields are delimiter-escaped. The client-policy generation is checked after retrieval and again after the receipt write, so a disable/enable cycle or revocation during a long visual query withholds the prepared result. Policy denials for valid same-user requests are recorded; operational failures are recorded best-effort. Malformed/oversized requests, protocol mismatches, wrong-user peers, and other failures before the capability handler are not recorded. Receipts are encrypted but not tamper-evident and can be cleared in the app.

The current identifier check is descriptive, not cryptographic. Packaging prefers an available Developer ID Application identity and enables the hardened runtime, with an explicit ad-hoc fallback for development, but the service does not verify a caller's code signature. A malicious same-user process can still claim the identifier of an enabled client. Users should not treat “Allowed clients” as protection from hostile software already running in their account.

The stable Developer ID requirement should preserve Passage's macOS Screen Recording and Accessibility identity across updates. Switching an existing installation from ad-hoc signing to Developer ID changes that identity and may require one fresh system permission grant. The package is not notarized.

## Measured performance

The encrypted 100,000-frame optimized-build benchmark measured 13.81 ms strict warm p50 / 33.35 ms p95, 21.04 ms conversational-rescue warm p50 / 42.64 ms p95, 0.07 ms zero-hit warm p50 / 0.10 ms p95, and 16.29 ms cold p50 / 36.05 ms p95 under the benchmark's new-connection definition. Recall first-page p95 measured 0.31 ms broad, 0.40 ms app+website, and 45.70 ms text+metadata; page-plus-asynchronous-facets measured 72.07 ms browse and 81.91 ms text+metadata p95, and a four-page, 124-hit cursor walk passed strict-order and uniqueness checks. Context-bundle search/build measured 132.05 ms p95 inside its 16,384-byte ceiling. It took 2,744.45 ms to encode/index the six-region-per-frame corpus plus materialized sessions. Database + WAL measured 147,014,656 bytes. The compact OCR-region blob measured 81 bytes/frame versus 615.62 bytes for the legacy JSON form, an 86.84% reduction. A separate million-row diagnostic reached 111.75 ms focused text+metadata p95 and 138.54 ms with extra cache/facet pressure, so the strict `<100 ms` lexical product gate remains open. The independent schema-v9 visual-index stress probe passes its store-only gate at 21.46 ms warm p95 unscoped and 42.05 ms p95 with exact app+website+time scope over one million unique scenes; it does not establish end-to-end hybrid latency or real-scene relevance. Methodology, prior-build comparison, and caveats are in [Performance evidence](PERFORMANCE.md).

## Future work — not implemented

The following items are product direction, not current behavior:

### Capture and privacy

- Browser integration that can verify private-tab state without relying on title/URL heuristics.
- Change-aware Accessibility diffs and field-level visual/text redaction beyond the current bounded focused-window snapshot and secure-field fail-closed rules.
- More complete multi-display, sleep/wake, lock/unlock, rapid-transition, and adversarial exclusion testing.

### Retrieval

- Project threads and saved lenses beyond deterministic activity sessions and safe resume targets.
- Scheduling and incrementally maintaining the dormant encrypted `MemorySegmentIndex`, benchmarking it at one million rows, and cutting Recall, Ask, Memory Capsule, and agent context bundles over to the shared runtime.
- Learned text-semantic retrieval and workflow-level ranking beyond the current local lexical + visual rank fusion.

### Agent security and capability

- Notarization, reproducible release verification, authorized application-identifier/provisioning support for the data-protection Keychain, and cryptographic executable identity verification for local clients.
- Per-request preview/approval for external agent requests, field-level release policy, and explicit screenshot-byte capabilities. In-app clipboard handoffs already require an exact preview and explicit copy.
- Tamper-evident access receipts and policy/credential boundaries for additional external providers.

### User experience and validation

- Time-range deletion with a preview and post-delete verification UI.
- Storage-health explanations that forecast retention impact before cleanup.
- Measured CPU, memory, energy, thermal, launch, OCR, media, and IPC performance on multiple Macs.
- First-run comprehension/usability studies comparing complete setup and Open Paused paths, permission refusal/recovery, and later onboarding replay.
- Formal VoiceOver, keyboard-only, increased-contrast, reduced-transparency, and reduced-motion verification.
